# 生产规范

单卡 GPU，**一次一镜**。这份文档讲怎么把一集排出来，以及出事了怎么办。

---

## 一、一次一镜，不是并发

单卡显存只有一块（实测 24G / 32G 都跑得动，但没富余到能并行）。
两个任务同时跑会互相抢显存，表现为其中一个 OOM 崩掉，**两个都白跑**。

所以：

- 一次只提交一个任务，跑完再提交下一个
- 需要排队时，服务照样收，`queue_depth` 会告诉你前面还有几个
- **不要因为轮询没返回就重复提交** —— 会占掉后面所有人的位置

批量出片时，在本地串成循环，不要并发：

```python
for shot in episode:
    job = submit(shot)
    wait(job)          # 阻塞到 done/failed
    collect(job)
```

## 二、两个质量档位

| 档 | steps | turbo | 一镜 5 秒 | 什么时候用 |
|---|---|---|---|---|
| 试片 | 8 | true | 约 7 分钟 | 确认人物、构图、台词有没有跑偏 |
| **交付** | 20 | false | 约 16~23 分钟 | 正式出片 |

**默认用 20 步。** 实测对比：8 步快一倍多，但多人同框口型会崩、语气偏机械；
20 步的画面、口型、人声全面更好。

推荐流程：

1. 8 步试一镜，看人物和构图对不对
2. 确认没问题，切 20 步重出这一镜
3. 剩下的镜直接 20 步

出片质量是客户验收的事，不是我们调优的目标 —— 按上面的档位出就行。

## 三、排一整集

### 1. 先把角色定妆照定死

每个角色先单独出图（每张约 30 秒），跟用户确认脸对不对。

**同一个角色，整集必须用同一份 `positive` 和同一个 `seed`。**
中途改 seed 或改描述，同一个人会在不同镜里长得不一样 —— 这是最容易翻车的地方。

### 2. 再逐镜出视频

`characters` 只列这一镜**出场**的人，按画面里从左到右（或任意固定顺序）编号，
prompt 里用 `<Picture 1>`、`<Picture 2>` 对应。

没出场的人**不要列**。列了会白占一个参考图口（H3 一共 7 个口），而且 H3 拿到
不需要的脸会干扰画面。

提示词写法见 `prompting.md` —— 尤其「导演指令词会被当台词念出来」那条。

### 3. 台词直接写进 prompt

H3 是 omni 模型，画面和声音从同一个联合潜变量一次出来 —— 提示词里写在引号里的
台词会被念出来，口型自动对上。**不需要外挂 TTS。**

配音那块（IndexTTS）只在需要**旁白/画外音**时用，走 `voiceover` 字段。

## 四、超出限制时怎么办

| 情况 | 处理 |
|---|---|
| 一镜超过 7 人 | 拆成两镜，或让用户减少同框人数 |
| 一镜超过 15 秒 | 拆成多镜（15 秒是 H3 的稳定上限） |
| 旁白超过 2000 字 | 拆成多镜，或分几次任务 |
| 显存不够 / OOM | 降到 1~2 个参考图；确认用的是 `fl2va` 权重而不是 `ref2va` |

## 五、故障排查

| 现象 | 判断 | 处理 |
|---|---|---|
| 提交 401 | token 错 | 核对 token；服务重启过的话看 `shot_token.txt` |
| 提交 404 | 地址/端口不对 | AutoDL 只映射 6006/6008，端口对不上就是 404（不是服务没起） |
| `/health` 返回 `ok:false` | 服务活着，连不上 ComfyUI | ComfyUI 挂了，先起它 |
| 任务一直 `queued` | 前面还有任务 | 正常，等前面的跑完 |
| 任务 `failed`，`error` 是"服务重启，任务中断了" | 跑的过程中服务重启了 | 重新提交一次 |
| 任务 `failed`，其它错误 | 采样阶段出错 | 重试一次；仍失败把 `error` 原文报给用户 |
| 出片了但 `result.video` 是 `null` | 服务版本旧 | 更新 `编排层/` 后重启 |

**服务重启会中断正在跑的任务**，这是设计如此（重启后原任务不可能自己接上，
标成 `failed` 比让它永远 `running` 更好排查）。重新提交即可。

## 六、服务的运行与恢复

服务部署在服务器上，机器重启/关机之后要手动拉起来：

```bash
cd /root/autodl-tmp/编排层 && sh start.sh -d
```

`start.sh` 会依次拉起 ComfyUI 和应用服务，**已经跑着的不会重复起**
（不会去抢 8188 端口）。跑完最后一行打印 `{"ok": true, ...}` 就是好了。

> `/health` 不带 token 会返回 401，那是正常的，不是服务坏了。
