# 分镜提示词怎么写

这份只写**在真机上验证过**的。写清楚"实测证据"是为了让你判断哪些能信、
哪些是我们的习惯写法。调不出效果的时候，先怀疑自己没按这里写。

---

## 一、台词：直接写在引号里，H3 会念出来

H3 是 omni 模型，画面和声音从**同一个联合潜变量**同一次前向出来。所以提示词里
写在引号里的台词会被念出来，**口型自动对上**，不需要外挂 TTS。

```
<Picture 1> 中的男子面色沉下来, 低声说: 你孤掌难鸣, 今日便是你的死期.
电影镜头缓慢推近. 声音: 男声, 庭院环境音, 风声.
```

**实测证据**：出片音轨能量起伏 259 倍，说话/停顿成段；而只写环境音的对照版
只有 9 倍（底噪型）。差异来自音频的段落结构，不是音量。

> 参考图口里的声音只用来**锁音色**（谁用什么嗓子），不决定说什么。
> 说什么由提示词决定。

## 二、⚠️ 导演指令词不能单列，会被当台词念出来

这是最容易翻车的一条，**实测过**：

```
❌ 他说: 你孤掌难鸣. 停顿. 今日便是你的死期. 语速偏慢, 语气愤怒.
```

写「停顿」，H3 就把"停顿"两个字**念了出来**。「语速偏慢」「语气愤怒」同理 ——
它们独立成词，就成了台词的一部分。

**演法必须融进句子描述里**：

```
✅ <Picture 1> 中的男子面色沉下来, 低声说: 你孤掌难鸣, 今日便是你的死期.
```

| 想表达 | ❌ 别这么写 | ✅ 这么写 |
|---|---|---|
| 停顿 | `停顿. 继续说...` | `他顿了顿, 继续说: ...` |
| 语速慢 | `语速偏慢` | `他缓缓地说: ...` |
| 愤怒 | `语气愤怒` | `他低吼着说: ...` |
| 迟疑 | `犹豫地说` | `他吞吞吐吐地说: ...` |

规律：**带"说"字的动作描述是演法，独立的名词/副词是台词。**

## 三、`<Picture N>` 对应 `characters` 的顺序

`characters` 第 i 个对应提示词里的 `<Picture i+1>`，从 1 连续编。

```
characters: [智伯, 赵襄子]
提示词:      <Picture 1> ... 智伯 ...
             <Picture 2> ... 赵襄子 ...
```

**谁出场写谁的编号，没出场的人不要列进 `characters`** —— 列了会白占一个
参考图口（一共只有 7 个），而且 H3 拿到不需要的脸会干扰画面。

---

## 四、⚠️ 有台词的角色，嘴一定要露出来

H3 忠实地照着参考图演。如果出图时下颌被胡须或口罩盖住了，
视频里**这个角色的口型一个字都看不出来** —— 不是模型不生成，是画面里就没有嘴可看。

**实测对照**（同一角色三种写法，同一 seed）：

| `positive` 里的写法 | 出图 |
|---|---|
| `thick lustrous black beard` | 浓密大胡子，下巴到嘴全遮住 |
| `short neatly trimmed black beard, lips unobstructed` | ❌ 照样浓密大胡子 |
| `short stubble beard, bare chin and bare upper lip` | ✅ 络腮胡茬，下巴和上唇都露出来 |

**措辞要具体**：`stubble` / `clean shaven` / `bare chin` 这类具体名词有效；
`neatly trimmed` 太虚，压不住模型先验。

> 顺带一条：`negative` 入参**不生效**（被 `ConditioningZeroOut` 清零，且 cfg=1），
> 所以"负面里写 `no beard covering the mouth`"没有任何作用，只能写进 `positive`。

---

## 五、⚠️ 景别要写明，否则出大远景

不写景别时，模型经常给一个**大远景** —— 人物在画面里只有几十像素，
口型、表情、服装细节全都看不清。

实测两次不给景别的出片，都是宫殿前的全景，人物小到无法判断口型。

```
✅ 中近景, 腰以上构图, 面部清晰占据画面三分之一.
✅ 近景, 面部特写, 眼神与口型清晰可见.
```

有台词的镜头尤其要写。写「电影镜头缓慢推近」**不能替代**景别 ——
推近是镜头运动，景别是初始构图，两个都要写。

## 六、声音声明

我们一直用这个写法，出片的环境音和说话声都正常：

```
声音: 男声女声, 庭院环境音, 风声.
```

写成「声音:」开头的一段，列出**谁在发声**和**环境底噪**。

> 说明：这是我们的习惯写法，多次出片结果正常，但**没有单独 A/B 验证过**
> "去掉这行会怎样"。属于「照着用没坏处」而不是「必须这么写」。

---

## 七、整集的角色一致性

**同一个角色，整集的 `positive` 和 `seed` 必须一模一样。**

- 改 seed → 同一个人在第 3 镜和第 7 镜长得不一样
- 改 `positive` 的措辞（哪怕意思一样）→ 脸也会变

实测确认：同 seed + 同 positive 出图是**逐字节一致**的，可复现。

一镜 7 个参考图口的分配建议固定下来（比如主角永远排第 1），
这样整集的参考图顺序也是稳定的。

## 八、一个能直接用的模板

```
中近景, 腰以上构图, 面部清晰占据画面三分之一. <Picture 1> 中的男子面色沉下来,
低声说: 你孤掌难鸣, 今日便是你的死期. <Picture 2> 中的女子疲惫地说:
晋室存亡, 尽在此夜. 电影镜头缓慢推近. 声音: 男声女声, 庭院环境音, 风声.
```

对应的 `characters`：

```json
[
  {"name": "智伯", "seed": 42,
   "positive": "adult man in his fifties, short stubble beard, bare chin and bare upper lip, dark red ceremonial robe, full body, cinematic still"},
  {"name": "赵襄子", "seed": 43,
   "positive": "middle aged woman, grey hair tied up, pale jade hairpin, deep green silk robe, full body, cinematic still"}
]
```

## 九、和业务参数的边界

提示词管不了这几件事，它们是接口字段：

| | 边界 |
|---|---|
| 时长 | `shot.seconds` 3~15（不是提示词里写"五秒"） |
| 画质 | `shot.steps` 4~40，8=试片 / 20=交付 |
| 画幅 | 用 `1344x768`，**别用 1.0MP**（会解析成 1376×768，超 H3 上限） |
| 音色 | `shot.voice` 指向 `input/` 里的声线文件 |
